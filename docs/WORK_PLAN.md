# Work plan: operator UI authentication, organization inventory, onboarding import

Status: active work plan, updated 2026-09-23. Completed packages and remaining external or deferred work are tracked in section 3. Designs: [operator UI authentication](GUI_AUTHENTICATION.md), [organization inventory](AWS_ORGANIZATION_INVENTORY.md), [onboarding import](ONBOARDING_IMPORT.md). Decisions: [ADR 0006](decisions/0006-OPERATOR_UI_AUTHENTICATION.md), [ADR 0007](decisions/0007-ONBOARDING_IMPORT_AS_UNMANAGED_OCCUPANCY.md).

The plan is cut so that most packages can be executed by a cheaper model at modest effort. That works only because each package is a closed contract: the files, the steps, the checks that must pass and the conditions under which to stop are all stated. A cheap model with a tight contract beats an expensive one with a vague request; raise the model or the effort only after the contract has been tightened and still fails.

## 1. Models and effort

| Tier | Claude Code | Codex CLI | Use for |
| --- | --- | --- | --- |
| **S** small | Haiku 4.5, effort `low`–`medium` | `gpt-6-luna`, `low` | tasks with an **external** checker: a stubbed CLI, a schema or YAML decode, a linter, a link check. Weak where the only check is a test the same model writes — it will pass its own tests with output that is wrong for the consumer |
| **M** medium | Sonnet 5, `medium` | `gpt-6-sol`, `medium` | self-contained code with table tests, Compose and Helm wiring; use Luna at medium only when an independent checker makes the result unambiguous |
| **L** large | Sonnet 5, `high` | `gpt-6-sol`, `high` | anything where a mistake is a security or availability defect but the design is already fixed |
| **X** expert | Opus 5, `high`–`xhigh` (or Fable 5.1) | `gpt-6-astra`, `high` | changes inside `internal/netbox` or `internal/service`; design papers; **reviewing** L packages |

The Codex routes above use the GPT-6 family described in the [current model guide](https://learn.chatgpt.com/docs/model-selection). [Codex pricing](https://learn.chatgpt.com/docs/pricing) lists Luna as the least expensive per token, then Sol, then Astra; a lower rate does not make a package cheaper if it needs retries. The [work-plan runner](../scripts/ai/run-work-plan) routes one queue item at a time, checks externally, and escalates once after a failed check. It does not infer a queue from this table: N4 names two historical entries, so the explicit [queue](../scripts/ai/work-plan-queue.json) uses unique IDs.

Starting a session:

```bash
claude --model claude-sonnet-5          # then set effort with /effort medium
codex -m gpt-6-sol -c model_reasoning_effort="medium"
```

Codex loads this checkout's [.codex/config.toml](../.codex/config.toml) in a fresh trusted session; [project tooling](AI_TOOLING.md) distinguishes config loading from MCP connectivity. [AGENTS.md](../AGENTS.md) is the shared project guide for Codex and Claude Code. Use `scripts/ai/run-work-plan --tool codex --list` or `--tool claude --list` to inspect the explicit queue; use `--all` with either tool to run it sequentially. The package contract and acceptance checks are shared; only the model route and agent CLI differ.

Evidence rule: an **S**-tier result is not accepted on its own word. In the first wave a small model returned correct setting names with invented line numbers, and called a metadata declaration "verified". Spot-check the load-bearing citations of every S package before building on it; that costs minutes.

Review rule: every **L** package is reviewed by an **X** model before it is accepted (`/code-review` in Claude Code, or `codex review`). Every package that changes code ends with `./tests/e2e/run-e2e.sh` green.

## 2. The contract every package follows

Give the executing model this, filled in from the package row and its detail block:

```
Package: <id and title>
Read first: <design doc section>, AGENTS.md, and only the files listed.
Change only: <files>. If another file must change, stop and report why.
Do: <steps>
Done when: <commands> all pass. Report each command, exit code, compact result and local log path; keep full logs out of the conversation.
Stop and report instead of improvising if: <conditions>
Never: run `go mod tidy` or otherwise change `go.mod`/`go.sum` (report a needed dependency instead); weaken or delete an existing test; publish NetBox's own port; set platform_allocation_id
outside internal/netbox Ensure; add a consumer API endpoint; commit (stage only).
Report: what changed, evidence, and what you did NOT verify.
```

Exit code 2 from a `scripts/ai/check-*` command means BLOCKED, not passed.

Two traps found while running the first wave:

- Writing Go source through an agent's file-write tool can turn a `\uFEFF`-style escape into the raw bytes. A raw byte-order mark anywhere but the first bytes of a Go file is a syntax error. Build such characters at run time from their byte values instead of writing them as literals.
- An agent's foreground shell command is capped at about ten minutes, and a NetBox started from an empty database takes longer than that to migrate. Packages that put the whole bring-up, test and tear-down into one background job and then waited for a notification stalled for hours: the job died, the throw-away project vanished, and nothing ever woke the agent. Work in phases that each fit one foreground call — `up -d` (returns at once), a bounded health-wait loop that is simply repeated until healthy, bootstrap, test, `down -v` — and give a runner script a phase argument as well as its one-shot mode. A package that has been "waiting for NetBox" for more than twenty minutes is stuck, not slow: check `docker compose ls -a`.
- Several agents running `scripts/ai/check-contract` at the same time see each other's half-finished links. A broken link in a file the package does not own is not that package's failure; re-run before concluding anything.

### Track F — adopting existing networks as allocations

Rules that hold for the whole track, in addition to section 2:

- **One constructor.** Today a committed allocation can come into being in exactly three places: one construction in `internal/service/service.go` (`Reserve`) and two assignments of `Committed` (`service.go`, `internal/service/worker.go`). ### Track G — the operator who is not a tenant

Found by [ADR 0008](decisions/0008-PLATFORM_OWNED_OPERATOR_UI.md), confirmed in the code on 2026-09-18. Every read is scoped by the caller's tenant: `List` and `Findings` filter on `TenantID`, `Pools` on `eligible_tenants` (`internal/service/service.go`). An identity must be onboarded to get past authentication, and onboarding demands a `tenant_id`, but nothing requires that tenant to be eligible for any pool. So an operator onboarded under a tenant such as `ops` receives `200` and an empty list from `/v1/pools`, `/v1/allocations` and `/v1/findings` — indistinguishable from a system with nothing in it. Domain-level findings such as `unmanaged_occupancy` are fanned out to each eligible tenant only, so that identity never sees them either.

The sharpest consequence is recent: `platform-ipam client findings --fail-if-open` (package E1), run under such an identity, **always passes**. It walks every page and refuses unreadable payloads, but there are no pages. A gate that can be satisfied by choosing who runs it is not a gate.

Two constraints frame any fix. `docs/API_V1.md` section 1: never accept a caller-supplied role claim, and an unauthorized object id answers `404` without revealing another tenant's allocation — both must keep holding for every non-operator. And `domain.Principal` has no role field today; ADR 0008 and ADR 0010 each named that gap and neither filled it.

**G1 · Decision record · X.** Design only, `docs/decisions/0011-…`, status **proposed**. Decide between, and take one position on: (a) an honest refusal — a principal whose tenant is eligible for no pool gets a distinct error on list endpoints instead of an empty `200`; (b) a read-only `operator` role set in the server-side identity file, never from a token claim, with cross-tenant reads on the `GET` endpoints, `tenant_id` exposed to operators only, and every write refused; (c) both, the refusal now and the role later. Work through: what the role may read and what it must never do (reserve, patch, bind, release — and `adopt`, which acts *as* a tenant and is deliberately a process mode, not an API caller); how `404`-not-`403` for foreign object ids survives for non-operators; whether findings and capacity need a domain-wide view rather than a union of tenant views; the effect on the OpenAPI contract and on the Terraform provider (none is acceptable; say so if true); how the identity file expresses it and how config validation catches an operator who is also eligible as a tenant; and what evidence moves it to accepted. It must relate to ADR 0006 (who can reach the NetBox UI) and ADR 0008 (no platform-owned UI), not contradict them silently.
