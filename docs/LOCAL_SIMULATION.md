# Local simulation before external validation

Status: local development route, 2026-09-23. The default integration environment remains Docker Compose. LS1 and LS2 have passed against isolated Compose projects; LS3 has passed a local kind chart-controller probe. It does not turn simulated results into stage, production, AWS, Entra ID, or Windows Active Directory evidence.

## Current Compose baseline

The core Compose stack exercises the API, worker, PostgreSQL ledger, NetBox, fake AWS observation service, REST/CLI/Terraform clients, onboarding, adoption, and operator permissions. The [end-to-end suite](../tests/e2e/README.md) is the integration gate. The 2026-09-23 isolated run passed 71 and 55 tests in its two discovery halves, the PostgreSQL storage suite, and `seed` against the development NetBox; see [the work-plan closeout](WORK_PLAN.md#3-packages).

The optional identity overlays use their own Compose projects. `tests/e2e/run-ui-entra.sh` drives a mock OIDC issuer through oauth2-proxy; its six tests cover admission by an Entra-shaped group object ID, rejection of an unrelated group and a group-overage-shaped token without a flat `groups` list, and header forgery. `tests/e2e/run-ui-ldap.sh` drives NetBox's LDAP backend against OpenLDAP; its seven tests cover viewer, maintainer, outsider, bad password, write denial and header forgery. On 2026-09-23 both suites passed locally, including an ORM check that neither LDAP user became a superuser. The projects were stopped with their volumes retained.

## Which simulator to use

| External dependency | Closest useful local exercise | What remains external |
| --- | --- | --- |
| AWS VPC/subnet observation and allocation recovery | Keep the deterministic `cloud-fake` Compose service for incomplete observations, lifecycle transitions, and safe-reuse refusals. The opt-in Moto service exercises real Go SDK EC2/STS requests with test credentials and a local endpoint. | Actual Organizations enumeration, cross-account IAM/SCP enforcement, account access, AWS resource state, and observed traffic. |
| Microsoft Entra ID | Keep the mock OIDC issuer and oauth2-proxy overlay. Exercise representative token claim shapes, group object IDs, overage refusal, callbacks and proxy header handling. | A real tenant's app registration, conditional access, MFA, Graph group lookup, token refresh and operational availability. |
| Active Directory | Keep OpenLDAP for the fast LDAP authorization gate. The separate Samba AD Compose overlay proves `sAMAccountName`, nested AD groups and LDAPS CA trust with the pinned NetBox image. | Windows AD behavior, forest/domain policy, enterprise PKI and actual directory latency/availability. |
| Stage/production Kubernetes | Continue Compose for application features and database behavior. A kind cluster ran this Helm chart with a local controller-probe image: migration and seed Jobs, workload readiness, Services, UI proxy and a failed upgrade hook. | Actual application startup under stage/prod settings, EKS Pod Identity, cloud load balancer, external DNS, real secrets/identity integration, managed control plane and production network policy implementation. |

**AWS choice.** LocalStack is useful for EC2 protocol coverage, but it is not a free full AWS Organization substitute: [Organizations is in its Ultimate plan](https://docs.localstack.cloud/aws/services/organizations/), while [IAM policy enforcement is disabled by default](https://docs.localstack.cloud/aws/developer-tools/security-testing/iam-policy-enforcement/). [Moto server mode and multi-account support](https://docs.getmoto.org/en/stable/docs/multi_account.html) provide portable request/response tests, with weaker authority and policy fidelity. The Moto image is pinned in `compose.aws-moto.yaml`; `tests/e2e/run-aws-moto.sh up|test|stop` exercises the real SDK's AssumeRole, GetCallerIdentity, DescribeAvailabilityZones, DescribeVpcs and DescribeSubnets path, including a wrong-account UNKNOWN result. `scripts/aws/org-inventory.sh` remains covered by stubbed CLI tests, not by this Moto test. The AWS SDK for Go supports [explicit service endpoints](https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/configure-endpoints.html); stage/prod `worker`/`adopt`/`api` settings refuse `AWS_ENDPOINT_URL`, `AWS_ENDPOINT_URL_EC2` and `AWS_ENDPOINT_URL_STS`. Neither emulator authorizes production CIDR reuse.

**AD choice.** A Samba AD DC is a closer Linux-based protocol counterpart to Windows AD than OpenLDAP. The [Samba container project](https://github.com/samba-in-kubernetes/samba-container) provides an AD server image, but its documented default requires a privileged container for filesystem extended attributes. The image is pinned by digest in `compose.ui-samba-ad.yaml`; its `/etc/samba` and `/var/lib/samba` volumes preserved users across a container recreate. `tests/e2e/run-ui-samba-ad.sh up|wait|bootstrap|test|stop` runs the seven NetBox login/permission tests, checks neither AD user became a superuser, and proves a trusted LDAPS bind succeeds while an unrelated CA is refused. It uses the generated CA from the isolated Samba state volume and publishes no AD port. The fast OpenLDAP gate remains available.

**Kubernetes choice.** [kind](https://kind.sigs.k8s.io/docs/user/quick-start/) runs actual Kubernetes nodes in Docker. The isolated `platform-ipam-ls3` cluster used kind v0.33.0/Kubernetes v1.37.0 and the chart's `ci/local-kind-values.yaml` with the test-only [`tests/kind` image](../tests/kind/README.md). Helm's migration hook completed before the API/worker Deployments appeared; a seed Job succeeded, all three Deployments reached 1/1, both Services answered, and the UI proxy refused `/api/` with 403. A migration hook deliberately failed on upgrade and the prior Deployments stayed ready at generation 1; restoring the dummy Secret allowed a successful upgrade. This proves chart controller behavior, not the application binary under stage/prod dependencies. LocalStack's EKS API simulation would not exercise the Kubernetes controller behavior this chart needs.

## Remaining gates

The LS1 and LS2 runners have `stop` phases that retain volumes for inspection. The local kind cluster and namespace also remain available for inspection. `check-compose`, `check-aws`, `check-helm` and the core Compose suite remain the regression gates for future changes.

The provider installation gap has a separate local rehearsal: `sh tests/e2e/run-provider-mirror.sh` built a test-only package and passed normal `terraform init`, provider schema loading, read-only lock reuse, and checksum rejection after package modification. This closes the local mirror mechanics check; it does not select a registry, release version, signing policy, or supported platform matrix. See [clients](CLIENTS.md#2-provider-implementation-contract).

The opt-in `tests/e2e/run-netbox-compat.sh up|wait|bootstrap|test|stop` probe ran the published NetBox Docker image `v4.6.10-5.0.2` in isolated Compose project `platform-ipam-ls4`. After first-run migrations, bootstrap and seed succeeded. The checked-in allocation/projection, viewer/maintainer role and UI proxy modules passed 14, 3 and 6 tests respectively. The project is stopped with volumes retained. This checks one additional 4.6 patch release; it does not establish a supported version range or cover the [4.7 minor release](https://github.com/netbox-community/netbox/releases). The test runner generates a fresh allocation run ID each invocation because reusing one would turn the capacity-delta check into an idempotent replay.

A fresh `platform-ipam-e2e-m4g` project on that image later passed the full 126-test suite. The optional AWS plugin built on the candidate digest, applied all five migrations on LS4, and served its accounts API with HTTP 200. LS4 is stopped with volumes retained; the M4g project's basic UI was later restarted for manual inspection. The exact-image support policy and completed local promotion gates are in [ADR 0019](decisions/0019-EXACT_NETBOX_RELEASE_SUPPORT.md). The M4g no-op projection check kept one managed prefix's `last_updated` unchanged across a development worker pass; [ADR 0017](decisions/0017-PERSISTING_ONLY_WHAT_A_LEDGER_TRANSACTION_CHANGED.md) records the bounded pilot and later 1,000-allocation measurement.

Real AWS, Entra ID, Windows AD, and stage/production validation remain external gates. The kind probe uses a small test image and dummy Secrets, so an actual chart rollout with the application binary and real dependencies is still unverified. M4g's 1,000-allocation local pass-time and successful during-pass reservation latency have now been measured on the 4.6.10 candidate: an unchanged projection made 1,000 GETs and no PATCHes in 64 seconds; a changed projection took 155 seconds. See ADR 0017 for the exact method and limits. A simulator cannot establish the actual customer estate size or stage/production latency.

The exact 4.6.10 image also passed six mock-Entra and seven OpenLDAP UI tests on separate Compose projects. A private 4.6.7 database backup was restored into a fresh local project and upgraded to 4.6.10: all 31 managed-prefix IDs, CIDRs and custom fields matched before and after, migrations were current, and a managed-prefix API read returned 200. See ADR 0019. These projects were stopped with their volumes retained. The `platform-ipam-e2e-m4g` basic-mode UI remains running on localhost port 18093 for manual inspection.

Do not run either emulator with production credentials or use its observations to authorize production CIDR reuse. All local identity and cloud fixtures belong to isolated Compose projects.
