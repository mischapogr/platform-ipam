# Local Helm controller probe

This is an opt-in local Kubernetes gate. The application itself is exercised by Docker Compose. The `tests/kind/probe.py` image accepts the chart's `migrate`, `api`, `worker` and `seed` arguments and serves the chart's health endpoints, so kind can verify the chart's Job and Deployment ordering without external AWS, OIDC, NetBox or PostgreSQL. It does not validate the real application binary under stage/production settings.

The 2026-09-23 run used kind v0.33.0 (Kubernetes v1.37.0), Helm 3.17.3, and the isolated cluster/namespace `platform-ipam-ls3`. The kind binary and kubeconfig were kept in `/tmp`; the cluster remains available for inspection. The test image was built locally and loaded with `kind load docker-image`. Its containerd manifest digest was tagged locally under `docker.io/platform-ipam/kind-probe@sha256:...` and passed to Helm as `image.digest`, with `image.pullPolicy: Never`; no registry push occurred.

The chart was installed with `ci/local-kind-values.yaml` and three disposable Secrets for its database URL, NetBox token and UI proxy bcrypt hash. Helm waited for the migration hook, then the API, worker and UI proxy Deployments each reached 1/1. Events showed the migration Job complete before the Deployment pods were created. From the API pod, the API and proxy Services answered 200 on their health paths, while the proxy returned 403 for `/api/ipam/prefixes/`.

For a failure gate, the disposable database Secret was changed to contain `fail-migration`; the probe's `migrate` command exited 7. `helm upgrade` failed at its pre-upgrade hook with `BackoffLimitExceeded`. All three old Deployments stayed ready at generation 1. The Secret was restored and a further upgrade succeeded with an enabled `operatorJob` in `seed` mode; its Job completed once. The release is deployed at revision 3.

To repeat the gate, use a new named kind cluster and namespace, build `tests/kind/Dockerfile`, load the image into kind, assign its manifest digest an image reference in containerd, and supply that digest with `--set image.digest=sha256:...` to Helm. The pinned Helm container is `alpine/helm:3.17.3`; mount a kubeconfig for that isolated cluster and run it with host networking so it can reach kind's localhost API endpoint. Create only disposable Secrets in that namespace. The chart's `ci/local-kind-values.yaml` is deliberately stage-shaped, but its endpoints are dummy values consumed only by the probe image. An actual stage/prod rollout and app startup require separate validation.
